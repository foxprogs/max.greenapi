# Тестовое задание. MAX Chat на GREEN-API

Веб-интерфейс для отправки и получения текстовых сообщений в мессенджере [MAX](https://max.ru)
через сервис [GREEN-API](https://green-api.com/max). Внешний вид — по мотивам https://web.max.ru/.

## Возможности

- Вход по учётным данным инстанса GREEN-API (`apiUrl`, `idInstance`, `apiTokenInstance`),
  проверка через `getStateInstance`.
- Создание чата по номеру телефона получателя: номер проверяется через `checkAccount`.
- Отправка текстовых сообщений — [`sendMessage`](https://green-api.com/v3/docs/api/sending/SendMessage/).
- Получение сообщений — [HTTP API](https://green-api.com/v3/docs/api/receiving/technology-http-api/)
  (`receiveNotification` / `deleteNotification`, long polling).
- Статусы доставки (отправлено, доставлено, прочитано, ошибка), счётчик непрочитанных.
- Подгрузка истории при открытии чата — `getChatHistory`.
- Сообщения, отправленные с телефона, тоже появляются в чате.
- Чаты и сообщения сохраняются в `localStorage` и переживают перезагрузку страницы.
- Адаптивная вёрстка: на мобильном — список чатов или открытый чат с кнопкой «назад».

## Стек

- React 19, TypeScript (strict), Vite
- Zustand (+ `persist`) — состояние сессии, чатов и сообщений
- Tailwind CSS v4
- Vitest — тесты, Biome — линтер и форматтер

Бэкенда нет: браузер обращается к API GREEN-API напрямую (API отдаёт CORS-заголовки).

## Локальный запуск

Нужен Node.js 22.12+. Подойдёт npm или Yarn — в репозитории лежит `yarn.lock`, но проект
ставится и через npm.

```bash
git clone <url-репозитория>
cd max.greenapi
npm install      # или yarn install
npm run dev      # или yarn dev
```

Приложение откроется на http://localhost:5173.

Остальные команды (`npm run <команда>` или `yarn <команда>`):

| Команда     | Что делает                                   |
|-------------|----------------------------------------------|
| `build`     | Проверка типов и production-сборка в `dist/` |
| `preview`   | Локальный просмотр собранной версии          |
| `test`      | Тесты (Vitest)                               |
| `lint`      | Проверка Biome                               |
| `typecheck` | `tsc -b`                                     |

## Настройка инстанса GREEN-API

1. Зарегистрируйтесь в [личном кабинете](https://console.green-api.com) и создайте инстанс MAX.
2. Авторизуйте в инстансе аккаунт MAX (по QR-коду). Статус инстанса должен
   стать `authorized`.
3. В настройках инстанса:
   - поле `webhookUrl` оставьте **пустым** — иначе уведомления уйдут на вебхук, а не в очередь
     HTTP API;
   - включите получение входящих сообщений, сообщений, отправленных с телефона и из API,
     а также статусов исходящих сообщений.
4. Скопируйте из личного кабинета `apiUrl`, `idInstance` и `apiTokenInstance` и введите их на
   странице входа.

Для проверки нужен второй аккаунт MAX: с него отвечаем на сообщения, отправленные из приложения.

## Как пользоваться

1. Войдите с данными инстанса.
2. Нажмите кнопку «Новый чат» в шапке списка и введите номер получателя: `+7 999 123-45-67`,
   `89991234567` или белорусский `+375 …` — других стран `checkAccount` не принимает.
3. Напишите сообщение: Enter — отправить, Shift+Enter — перенос строки.
4. Ответ получателя появится в чате, как только придёт уведомление.

Кнопка выхода удаляет учётные данные, чаты и сообщения из браузера.

## Как устроено

```
src/
  api/          — HTTP-клиент, типизированные методы GREEN-API, типы ответов
  store/        — Zustand: сессия и чаты/сообщения (persist в localStorage)
  hooks/        — цикл опроса уведомлений, загрузка истории
  lib/          — разбор уведомлений и истории, номера телефонов, форматирование
  features/     — экраны: вход, список чатов, чат
  components/   — общие компоненты (аватар, иконки)
```

**Получение сообщений.** Один цикл на сессию: `receiveNotification` с `receiveTimeout=20` →
обработка → `deleteNotification`. Уведомление удаляется из очереди всегда, даже если его не
удалось разобрать, иначе очередь встанет. При сетевых ошибках — повторы с экспоненциальной
задержкой от 1 до 30 секунд; при возвращении сети (`online`) — переподключение сразу.
На 401/403 опрос останавливается и предлагает войти заново.

**Отправка.** Сообщение сразу появляется в ленте со статусом «отправляется», после ответа
`sendMessage` получает настоящий `idMessage`. При ошибке — статус «ошибка» и кнопка «Повторить».

**Чат по номеру.** В уведомлениях и истории MAX `chatId` — внутренний id пользователя, а не
`номер@c.us`. Поэтому при создании чата номер сначала проверяется через
[`checkAccount`](https://green-api.com/v3/docs/api/service/CheckAccount/), как советует
документация: чат сразу заводится под внутренним id, и все уведомления, история и отправка идут по
нему. Если на номере нет аккаунта MAX, об этом сообщается сразу. Для номера, чат с которым уже
есть, проверка не повторяется.

**Фильтрация.** Показываются только текстовые сообщения (`textMessage`, `extendedTextMessage`).
Реакции, медиа и прочие типы уведомлений пропускаются, но удаляются из очереди.

## Ограничения

- **Только текст.** Медиа, файлы, группы, редактирование и удаление сообщений не поддерживаются.
- **Лимиты тарифа.** Если тариф ограничивает число собеседников, при превышении API возвращает
  ошибку 466 — приложение показывает понятное сообщение.
- **`getChatHistory` — не чаще 1 запроса в секунду** на инстанс. При быстром переключении чатов
  сервер может ответить 429 — запрос повторяется через секунду, история появится с задержкой.
- **Частые проверки номеров** через `checkAccount` MAX ограничивает (ошибка 469): приложение
  покажет сообщение, проверки стоит приостановить на пару часов.
- **Учётные данные хранятся в `localStorage`.** Это осознанный компромисс для демо без бэкенда:
  не используйте приложение на чужих устройствах, выходите из аккаунта кнопкой выхода.
- **Одна вкладка.** Очередь уведомлений у инстанса одна: при нескольких открытых вкладках (или
  другом клиенте HTTP API на том же инстансе) уведомления разойдутся между ними.
- Имена контактов и аватары не загружаются — чат подписан номером телефона.
